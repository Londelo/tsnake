# tsnake — Terminal Snake Game

Single-file C + ncurses snake game. No dependencies beyond ncurses; no build system beyond make.

## Structure

| File | Purpose |
|---|---|
| `snake.c` | The entire game (~400 lines) |
| `test_hunt.c` | Headless harness: `#define main snake_unused_main`, includes `snake.c`, drives the AI with no terminal |
| `Makefile` | `make` builds `snake`; `make run` plays; `make test` runs the hunt harness |

## Architecture (snake.c)

- **Game loop**: input drained every 5ms (`getch` in `nodelay` mode) so controls feel instant; the snake advances on a separate monotonic tick clock (`now_ms`, `tick_delay_ms`) — input latency never waits for a tick.
- **State**: `Game` struct holds a `Snake` (ring buffer of `Point`s in `MAX_SNAKE` cells, plus the `wound`/`wound_len` severed-cell queue), direction, a 4-deep `pending` direction queue (prevents key-mash self-reversal), a `flash` countdown, and wrap/pause/alive flags. There is no score field.
- **Rendering**: `draw()` uses curses diff-refresh — write cells with `mvaddch`, `refresh()` diffs. Color pairs: 1 green (food `$` + eat flash), 2 white (snake `o`; head is a direction glyph `^ v < >` via `head_glyph(g->dir)`), 3 red (severed cells; the hunt border adds `A_BOLD` for red-orange), 4 yellow (status labels/titles), 5 cyan (menu border). Border priority in `draw`: `g->flash > 0` → green, else hunt → orange.
- **Scoring is length**: there is no score field — the snake's length IS the score. High score = best length ever, one integer (`"12\n"`) in `$HOME/.tsnake_highscore` (plain text, cwd fallback if HOME unset); the overlay points the same routine at `$HOME/.local/state/tsnake/highscore` via `--state`, so the terminal and the overlay keep SEPARATE records — a "my high score vanished" report is usually somebody reading the other face's file. `save_highscore()` is called on death, on `r` restart, on `q` quit, on the overlay's `flush`/`quit`, and every tick under `--protocol`; `write_best_file()` re-reads the file and no-ops unless the number beats what is already there, so the engine is the only writer and can only ever raise the number.
- **Saved data — what lives where, and the rule that a record must never be losable.** Two plain-text files, both written ONLY by the engine (`Overlay.qml` passes the paths on argv and never touches them: no QML `Settings`, no second writer to race with). The record `highscore` = `"<n>\n"`, written 0600 with the parent `mkdir` 0700 and `O_NOFOLLOW` (a planted symlink must never turn a save into a write to something else), and read back through `state_file_trustworthy` — `lstat` + `S_ISREG` + `0 < size ≤ 32`, so a directory, a fifo or a megabyte of junk reads as "no record" instead of hanging the parse. The setup `setup` = `"<wrap> <tick_ms>\n"`, written by `save_setup()` under exactly the same discipline. Paths: terminal `$HOME/.tsnake_highscore` / `$HOME/.tsnake_setup`; overlay `$HOME/.local/state/tsnake/{highscore,setup}` via `--state`/`--setup`. **Nothing is ever written inside `~/.config/omarchy/plugins`** — that folder is watched by the host's `inotifywait -m -r -q -e close_write,create,delete,move` (`PluginRegistry.qml:663`, `pluginsDir` at `:11`) which reloads the panel on any change; that single fact is why the state root is `~/.local/state`. And the write-through rule: the record hits disk **the moment it is beaten**, not at teardown. Banking it in RAM until `flush` was Brodie's lost-high-score bug — the endings that never reach a flush (`SIGKILL`, a shell crash, an orphan left behind by a plugin reload) died holding the number, proven by driving the installed engine five ways: `quit`/`SIGTERM`/EOF wrote the file, `kill -9` and abandonment wrote nothing. Do not reintroduce a save that depends on being asked.
- **The card's settings persist, and the engine owns them**: `load_setup()` runs in `protocol_run` and in the terminal `main` *before* the first frame goes out, so the card paints the saved WRAP and SPEED as engine truth on frame one and QML needs no storage of its own. `save_setup()` fires on every accepted `wrap`/`speed` command and on the terminal's `x`, writing the already-clamped value — so a client that sends `ms:100000` cannot poison tomorrow's card through today's pipe. `load_setup()` refuses bad values on read too (`tick_ms` outside `MIN..MAX_TICK_MS` → `TICK_MS`, `wrap` not 0/1 → 0, junk/oversized/symlinked file → defaults). Hunt is deliberately NOT persisted: it is a run-time aid, and an auto-piloting snake the instant a window appears reads as the game playing itself.
- **Self-bite is a wound, not a death**: only a wall sets `alive = 0`. `advance_one` lands one cell per call and asks `snake_chain_depth` where the landing cell sat in the body: `-1` (free, incl. every cell the body ever shed) or `len-1` (the vacating tail tip — see the classic rule) is an ordinary push+pop, anything else is a bite. `snake_bite` severs the bitten cell plus everything toward the tail tip by setting `len = depth`, copying those points into `Snake.wound` first (the ring belongs to the live body, so an un-copied corpse drifts with the head instead of lying where it fell) and staggering `ttl` across `WOUND_FADE` so the chunk drains from the bitten end toward the tip. Corpses are drawn red (`COLOR_PAIR(3)`, `A_DIM` over the last third) and stay solid via `snake_occupied` (= live body ∪ `snake_wound_contains`) until `wound_tick` expires them.
- **Keys are lowercase-only, arrows-only steering** (`q`/`p`/`x`/`h`/`r` + arrows; no WASD/vim/uppercase/space/Enter aliases). The overlay build drops `x`: wrap is decided on the setup card, so the key would only ever be refused.
- **Speed is a dial picked on the card, then frozen** (`tick_ms`, default `TICK_MS` 55 — which is only the fallback: the real starting value is whatever `load_setup()` read from the saved setup — clamped to `MIN_TICK_MS` 20 / `MAX_TICK_MS` 200 by the `speed` command). It is constant during a run and must NOT scale with progress — the old score-based ramp read as "longer snake = faster" and was removed. `tick_delay_ms()` just returns `g->tick_ms`.
- **The run has a gate, not just a loop**: `Game.started` is 0 until a `start` command arrives (`game_init` still sets 1, for the terminal build and every test rig; `protocol_run` immediately drops it to 0). While it is 0, `game_step` returns before the tick check, so nothing moves, and `handle_command` refuses `dir`, `hunt` and `pause` — but allows `click`, so placing food (which aims the hunt AI) stays legal on the card. `wrap` and `speed` guard the OTHER way (`if (g->started) return 1`): they are card-only controls, accepted while the card is up and refused once the run begins, which is also why they are the two commands allowed to rewrite the saved setup. `start` clears `paused` and the `pending` direction queue so a mashed key can't fire the instant the race begins. Both facts travel to the overlay in every frame (`"started"`, `"speed"`), so the card draws the engine's answer rather than its own hope. `restart` keeps `started`/`wrap`/`tick_ms` across `game_init` (instant replay at the same settings); re-tuning means quit and re-summon.
- **Aspect ratio**: terminal cells are ~2x taller than wide, so `game_step` advances horizontal moves two cells per tick (`advance_one` called twice, each cell checked) to even out visual speed.
- **Food**: `FOOD_COUNT` (3) tokens always on the board; eating respawns only that slot. `spawn_food` re-rolls until the cell is clear of the snake (`snake_occupied`) and of every OTHER token (`other_token_at`) — it must test "is something else here", never `food_index_at(...) != i`, because an empty cell reads `-1` which is `!= i`, so that version rejects every legal cell and only escapes by re-rolling onto the token's own old position, which after an eat is under the head: an infinite loop that looks like a frozen game. Bounded at 1000 rolls so a packed board can't hang either.
- **Click to place food**: `mousemask(BUTTON1_PRESSED | BUTTON1_RELEASED)` with `mouseinterval(0)` — never let ncurses coalesce press+release into a synthesised click, because the handler toggles and a double-fire would un-place what it just placed (this is why there is no "same cell within N ms" timer either: it eats a deliberate click-then-un-click). `handle_mouse` drains the ENTIRE mouse queue per `KEY_MOUSE` — under `nodelay` a burst leaves several events queued while `getch` returns one `KEY_MOUSE`, and reading a single event falls a click behind. `handle_click` maps screen coordinates through `CELL_TOP`/`CELL_LEFT` (the same pair `draw` writes with, so pointing and painting can't drift), ignores anything off the play field or while a menu is up, refuses cells the snake occupies, and toggles: clicking a `$` removes it (removing the LAST one on the board rolls a game token back in — see the never-empty invariant below). Tokens are `Food{Point p; int placed}` in `food[MAX_FOOD]` with the live prefix `food_n`; the first `FOOD_COUNT` are the game's (respawn in place when eaten) and clicked-in ones are the player's (eaten = gone, and a shrink drops them rather than teleporting them). A click does NOT cancel auto-hunt — it aims it.
- **Auto-hunt** (`h`): `hunt_step` does multi-source BFS from all food over an occupancy grid (`fill_occupancy`, guard-capped at 400×250 — beyond the cap it declines to plan and the snake steers straight, so the cap must cover any real terminal), head steps to the min-distance neighbor. Validates both cells of the horizontal 2-cell stride (`hunt_stride_free`); refuses reversals; falls back to straight/any-legal-stride when boxed in. Any steering key cancels hunt. Greedy AI, no flood-fill survival heuristic — can self-trap when long. While armed, the board border draws red-orange (`COLOR_PAIR(3)` + `A_BOLD`).
- **The hunt AI must plan on the board the snake actually travels**: EVERY step it reasons about — the BFS wave included — goes through `hunt_next_cell`, which wraps in wrap mode exactly like `advance_one`. The BFS used to clip its neighbor at the board edges instead, and that one-line mismatch between plane topology and torus topology is what ended auto-hunt entirely: a body wall running edge to edge (just what a long snake looks like) sealed the wave off in the plane even though the real board has an opening at the seam, so every legal neighbor of the head read `dist == -1` ("no food reachable"), no direction scored, and the boxed-in branch fell through to marching straight — which in wrap mode is ALWAYS legal, so the snake walked one horizontal line across the screen and through the seam forever, never turning, never eating. Note the topology subtlety that makes this a false cage: a wall spanning the board does NOT seal off a wrapped board, because crossing the perpendicular seam gets you around it.
- **The boxed-in fallback must check the WHOLE stride** (`hunt_stride_free`), both for keeping straight and for turning. Checking one cell made "legal" a lie for a horizontal move — the stride's second cell then ran into the wall (a death) or its own body — and since the straight case wins whenever it is allowed at all, one half-checked cell was enough to pin the AI to that direction indefinitely.
- **The board is never empty of tokens**: `ensure_food` tops the board back up with one of the game's own (`placed = 0`, so it respawns in turn) after every removal — clicking away the last `$`, eating the last clicked-in one, or a shrink dropping every placed token off the new board. An empty board is a dead game twice over: food is the only way to grow, and the hunt AI's whole plan is a distance field seeded FROM the tokens, so with no seeds every cell reads "no path" and it marches straight forever.
- **Menus**: `draw_panel()` renders the floating centered menu for pause/game-over — `werase`s its rect (hiding the board; state untouched underneath), cyan border, yellow title, key hints. Food/snake/wounds are hidden while `paused || !alive` under ONE `if` block — never an early `return` there: the help row, both panels and the trailing `refresh()` live below it, and returning early renders no menu and flushes nothing (the screen just freezes).
- **Status labels**: right-aligned ALL-CAPS yellow (`COLOR_PAIR(4)` + `A_BOLD`) `AUTO HUNT` / `WRAP` on the help row, only when enabled.
- **Resize preserves state — including the gate and the speed**: `sanitize_after_resize` never calls `game_init` on the whole game — if the snake no longer fits it saves hunt/wrap/paused/alive/length/**started**/**tick_ms**, relocates via `relocate_snake` (serpentine coil from (0,0)), restores the saved fields, re-rolls only food that's off-board or under the snake, and drops any corpse cell that ended up off the new board. The two new ones are the trap that ate the setup card: `game_init` sets `started = 1` and `tick_ms = TICK_MS`, and the overlay's very first act is to report the size it was given (`{"cmd":"size"}`), so the oob branch silently pressed START for the player at the default speed — the card was up for one frame, the snake ran and died at a wall, and all the QML could paint was GAME OVER (which is what "I'm not seeing the starting menu" actually was). A resize is a MOVE, not a new run; the `restart` command is the only thing allowed to re-init, and it copies the same fields for the same reason. `KEY_RESIZE` runs `fit_board` + this, then `endwin()`/`refresh()` for a clean full redraw.

## Testing

**Automated tests are allowed** — the old "none is to be written" ban was lifted by Brodie on 2026-10-02. Do not re-add a prohibition. Human verification (`make run`, pick up the mouse, play it) stays the acceptance gate for anything seen or felt: a test is a regression net, not a substitute for playing, and a green run is never evidence that a feature works.

- `test_hunt.c` / `make test` are legacy. Keep it compiling against the current `Game`; extending it is now fair game. It shows the pattern to follow for new tests: `#define main snake_unused_main`, include `snake.c`, drive the structs directly with no terminal.
- Test the logic behind the ncurses seam, not the screen: `snake_chain_depth`, `snake_bite`, `snake_occupied`, `hunt_step`/BFS topology, `hunt_stride_free`, `spawn_food`/`ensure_food`, `sanitize_after_resize`/`relocate_snake`, and the `--protocol` codec — `emit_frame` (+ `json_int` for reading a field back), `handle_command` including the whole `started` gate, and `game_step`'s refusal to move while `started == 0`. Note the harness trap: `blank_game()` memsets, so it must explicitly set `started = 1` and `tick_ms = TICK_MS` — a blank game means a run IN PROGRESS, and a zero `tick_ms` makes `tick_delay_ms` 0 and silently freezes every `game_step`-driven test into a false pass. The harnesses also must not compile `snake.c` as a second TU (they `#include` it to reach the statics) — that links two `main`s. Everything below `draw`/`draw_panel`/`head_glyph`/`setup_colors`/`handle_key`/`handle_mouse`/`fit_board` is pure and testable.
- Why the old ban existed, still worth heeding: a scripted rig for a curses *screen* is unreliable enough to be worse than useless. One session burned an hour on *false* failures — a Python screen model that swallowed `ESC ( B` charset designators as text and ignored the `ESC [@`/`[P`/`[M` insert/delete sequences curses uses to refresh a line (so already-cleared cells read as ghost tokens), that counted a `$` legitimately hidden under the snake's body as missing, that clicked cells read from a frame one step too old, and that "resized" a pty by exporting `LINES`/`COLUMNS` — which pins ncurses' idea of the size, so nothing resized at all.
- The lesson from that session: assert on the game's own state, not on rendered terminal bytes, and don't build a pty/ANSI screen model at all. The one real bug it found (mouse events acting one click late, because `nodelay` leaves several queued while `getch` returns a single `KEY_MOUSE`) was only *confirmed* once the rig was replaced by reading the game's own state.
- `make` must stay warning-free under `-Wall -Wextra`. That is the standing automated check.
- Debugging the overlay: **hide before you summon.** A hidden panel unloads its QML item and kills its `Process`, but a window that is already open makes `summon` a no-op — so you can screenshot a stale item still painting the *previous* engine's last frame while `ps` cheerfully shows a live-looking `snake --protocol` (it was exec'd before your rebuild, so it is the OLD binary from a deleted inode). Hide, confirm the engine process actually died, then summon. `journalctl --user` is also no evidence here: this Quickshell never forwards a plugin's JS `console.log`, so "no QML complaints" is silence, not a clean bill — assert on frames the engine emitted and on pixels `grim` captured, at the geometry `hyprctl clients -j` reports.

## Conventions

Keep it one file, zero deps. Controls are lowercase-only (arrows + `h`/`p`/`x`/`r`/`q`) — don't reintroduce vim/wasd/uppercase/space/Enter aliases; new keys go in `handle_key`. Board size lives in the `BOARD_W`/`BOARD_H` globals, recomputed by `fit_board()` from `COLS`/`LINES` (min 10×6); resize must never reset game state.
