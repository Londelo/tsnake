# tsnake — Terminal Snake Game

One file (`snake.c`), zero deps beyond ncurses, instant startup: `make`, `make unit` (the real test suite), `make run` (play). It has TWO FACES over one engine: a terminal curses build, and `snake --protocol` — the same rules, tick clock, wounds and AI with NDJSON over stdin/stdout instead of a screen, which the Omarchy/Quickshell overlay (`Overlay.qml` + `BarWidget.qml` + `GlyphLab.qml`) drives as a child process. The overlay is a face, not a second game: `snake.c` is the single source of truth for the rules (protocol grammar: `docs/protocol.md`). `make test` runs `test_hunt` — a legacy print-only rig that asserts nothing; kept offered (it must keep *compiling*), but a clean `make test` is silence, never a pass.

## Keys

Lowercase-only, arrows-only steering: `q`/`p`/`x`/`h`/`r` + arrows (no WASD/vim/uppercase/space/Enter aliases; new keys go in `handle_key`). The overlay build drops `x` — wrap is decided on the setup card, so the key would only ever be refused.

## Traps (each one has bitten once — full stories in `docs/decisions.md`)

- **Scoring is length**: no score field — length IS the record (`"12\n"`).
- **The record hits disk the moment it is beaten**, never at teardown (the `EPIPE`→`_exit` fact from the daemonize era travels with it: a pipe that closes mid-write must kill the engine, not orphan it — the same reason the write-on-beat rule exists: endings that never ask for the `flush` really happen, `SIGKILL` included). Terminal face: `$HOME/.tsnake_highscore` + `$HOME/.tsnake_setup` (cwd fallback if HOME unset). Overlay face: `$XDG_STATE_HOME/tsnake/{highscore,setup}` (else `~/.local/state`) via `--state`/`--setup`, written by the engine alone. **Neither file ever lives inside `~/.config/omarchy/plugins`** — that tree is inotify-watched and reloads the panel on any change, and `omarchy-plugin-remove`/`-update` can delete or `reset --hard` the folder (the host's own 11 first-party plugins keep state under `~/.local/state/omarchy/`; none in the plugin folder).
- **Code lives in the plugin folder, state lives in `$XDG_STATE_HOME`.**
- Horizontal moves take a **2-cell stride** (cells are ~2x taller than wide); `hunt_stride_free` checks the WHOLE stride, `hunt_next_cell` wraps exactly like `advance_one` — plan on the board the snake travels, or the AI marches straight forever.
- The **`started` gate**: a resize is a MOVE, not a new run — `sanitize_after_resize` never re-inits (a resize once silently pressed START: the overlay's first act is a `{"cmd":"size"}` report).
- **The opening order** (Brodie, 2026-10-13): black screen → engine → first frame → setup card. Nothing paints before the engine's first frame — no HUD, no help row, no card (`gotFrame` gates them all); the error panel replaces the black screen if no frame ever lands.
- `stateUsable` (`Overlay.qml`, with its `stateFile`/`setupFile`/`argv` chain) refuses a root-ish state path, and `state_file_trustworthy`/`O_NOFOLLOW` (`snake.c`) refuse a junk or symlinked save file.
- `spawn_food`: ≤1000 re-rolls, and `other_token_at` must test "is something else here" (an empty cell reads -1, which `!= i`).
- Mouse input: `mouseinterval(0)`, never coalesced; `handle_mouse` drains the whole queue per `KEY_MOUSE`.
- `snake_chain_depth` scans tail-first: the vacating tail-tip is a legal landing square; a self bite is a wound, not a death.
- The board is **never empty of tokens** (`ensure_food`) — an empty board is a dead game twice over.
- **Harness**: `blank_game()` memsets, so it must set `started = 1` AND `tick_ms = TICK_MS` by hand (a zero `tick_ms` freezes every `game_step`-driven test into a false pass); harnesses that `#include "snake.c"` must never let `snake.c` compile as a second TU (two `main`s). `test_hunt.c` asserts nothing (it prints `hunt_step`/`alive`/`len` and exits 0 whatever happens; its 200-tick loop lets the rig steer a self-severing body blind); `make test` still runs it, but never offer it as proof. `test_game.c` writes its state files under a per-process `/tmp/tsnake_unit_<pid>/` scratch dir and wipes that dir at exit — the wipe and its `/tmp/tsnake_unit_` prefix guard are load-bearing. Its 3 formerly-red checks now pass, and the old "shared rig state" diagnosis was wrong: the flush pair needed `flush_setup()` to be re-entrant (the bank is never spent — the file can be gone by the time the terminator asks), and the click pair was clicking a corner cell where `tokens_far()` parks a token, and a click on a token cell REMOVES it (the handler toggles) — a rig bug, not a game bug. Baseline as of 2026-10-10: 2324 checks, 0 failures.
- `data/glyphs.json` is data, not code — `install.sh`'s named-file copy-list ships it and the `docs/` pair into the plugin folder. Marketplace installs deliver git-tracked files only and run nothing — no lifecycle hook exists anywhere in the host (measured: `omarchy-plugin-enable` and `PluginRegistry.qml` spawn no plugin code), so the overlay's first summon builds the engine itself via `make` into `$XDG_STATE_HOME/tsnake/build` — never the watched plugin folder — and `install.sh` stays the by-hand path. `plugin remove` deletes the code and leaves the record standing; that is the host's convention, not an oversight.
- **Overlay debugging: hide before you summon** — a summon against an open window screenshots the stale item, and `journalctl` silence is not evidence.

## Testing

**Automated tests are allowed** (ban lifted by Brodie, 2026-10-02 — do not re-add a prohibition). Human verification (`make run`, pick up the mouse, play it) stays the acceptance gate for anything seen or felt: a test is a regression net, not a substitute for playing, and a green run is never evidence a feature works. `test_game.c` (via `make unit`) is the real suite — keep it compiling against the current `Game`.
